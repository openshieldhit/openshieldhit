\begin{frame}{The shape of the problem}
  \begin{columns}[T]
    \begin{column}{0.54\textwidth}
      \small
      A Monte Carlo run is \textbf{$N$ independent histories}.
      \medskip

      \textbf{Compute} is embarrassingly parallel: each history is a private
      random walk through the geometry. Profiling confirms 80--86\,\% of wall
      time is the transport step, throughput flat in $N$ — \emph{compute-bound}
      (PR \#162).

      \medskip
      So the hard parts are \textbf{not} the physics — they are:
      \begin{itemize}
        \item \textbf{Scoring} — many histories write the \emph{same} voxels.
        \item \textbf{Memory} — what is \textcolor{oshGreen}{shared \& read-only}
              vs.\ \textcolor{oshAmber}{private \& written}; for a CT it explodes.
        \item \textbf{Load balance} — histories cost differently; we may want
              \emph{run-by-time} or unequal work per worker.
      \end{itemize}
      \footnotesize\color{oshGrey}(A reproducibility \emph{contract} also has to
      be stated — but it is a definition, not a blocker. See later.)
    \end{column}
    \begin{column}{0.46\textwidth}

\begin{frame}{Vocabulary — five words this deck leans on}
  \small
  \begin{columns}[T]
    \begin{column}{0.5\textwidth}
      \textbf{cold $\to$ hot.}\\
      \textcolor{oshGreen}{\emph{Cold}} = parsed-and-compiled input
      (geometry, materials, tables). Built once, then \textbf{read-only}.
      \textcolor{oshRed}{\emph{Hot}} = per-history state that changes every
      step (particle pool, RNG, tallies). Only the hot state needs a parallel
      story.
      \medskip

      \textbf{stream.}\\
      Each history has its own random-number \emph{stream}, derived from its
      global index — a private, repeatable sequence of draws. Independent
      streams $\Rightarrow$ histories can run in any order, on any worker.
      \medskip

      \textbf{64\,B cache line.}\\
      Memory moves between cores in 64-byte \emph{lines}, not single values.
      Two cores touching \emph{different} numbers in the \emph{same} line still
      fight over it — ``false sharing''. Layout decides performance.
    \end{column}
    \begin{column}{0.5\textwidth}
      \textbf{AoS vs SoA.}\\
      \emph{Array of Structs}: \code{[\{x,y,z,E\},\{x,y,z,E\},\dots]} —
      one particle's fields together.\\
      \emph{Struct of Arrays}: \code{x[\,],y[\,],z[\,],E[\,]} —
      one field for \emph{all} particles, contiguous. The pool is SoA so a
      kernel over one field is a single vector load (no gather/scatter).
      \medskip

      \begin{tikzpicture}[scale=0.9]
        \node[ann] at (0,1.7){AoS};
        \foreach \x in {0,1.35,2.7}{
          \node[cell,minimum width=1.15cm,fill=oshGrey!12] at (\x,1.3){x y z E};}
        \node[lbl] at (1.35,0.85){a lane strides over a struct};
        \node[ann] at (0,0.35){SoA};
        \foreach \x in {0,0.5,1.0,1.5,2.0,2.5,3.0}{
          \node[cell,minimum width=0.45cm,fill=oshSky!18] at (\x,-0.05){};}
        \node[lbl,text=oshSky] at (1.5,-0.5){\code{x[\,]} contiguous — one SIMD load};
      \end{tikzpicture}
    \end{column}
  \end{columns}
\end{frame}

\begin{frame}{How much parallelism? The target machines}
  \begin{columns}[T]
    \begin{column}{0.5\textwidth}
      \small
      The right strategy depends on \emph{how many} workers and \emph{how much
      RAM each} we are scaling to:
      \begin{itemize}\itemsep2pt
        \item \textbf{Laptop} — easily $\sim$10 cores today.
        \item \textbf{Ares} (Cyfronet) — \textbf{48} cores/node.
        \item \textbf{Athena} (Cyfronet) — \textbf{128} cores/node, but a
              \emph{GPU-first} machine (8$\times$A100/node).
        \item \textbf{Helios} (Cyfronet) — \textbf{192} cores/node; large
              GPU partition (Grace+Hopper).
      \end{itemize}
      \medskip
      \textbf{Memory per core is the tight one:} $\sim$2--4\,GB/core across the
      board (Athena a little more; a laptop is similar). That budget — not the
      core count — is what decides \textbf{B vs.\ C} for a big CT.
      \medskip

      \footnotesize\color{oshGrey}
      Two regimes: $\sim$10 cores (shared memory, threads) and $\sim$50--200
      cores (one fat node, still shared memory) before MPI across nodes even
      enters. Athena/Helios also push us toward the GPU path (Strategy D).
    \end{column}
    \begin{column}{0.5\textwidth}
      \centering
      \begin{tikzpicture}
        \begin{axis}[
            xbar, width=6.6cm, height=4.4cm,

      $M_\text{shared}+T\,M_\text{private}$ in node RAM.
    \end{column}
  \end{columns}
\end{frame}

\begin{frame}{Architecture already built for it: cold $\to$ hot}
  \begin{columns}[T]

      \small
      The app layer parses files into \textbf{four cold workspaces}, then
      \code{*\_prepare()} compiles them into immutable runtime state.

      \medskip
      \textbf{Key for parallelism:} once prepared, the
      \textcolor{oshGreen}{cold/compiled state is read-only}. It can be
      \emph{shared} by every worker with zero coordination.

      \medskip
      Only the \textcolor{oshAmber}{hot, per-history state} (RNG, particle

\begin{frame}{The foundation: per-history RNG streams}
  \begin{columns}[T]
    \begin{column}{0.5\textwidth}
      \small
      Independence is decided \emph{before} any thread exists.

      \smallskip
      \code{osh\_rng\_seed\_history(rng, type, seed,\\ hist\_index, purpose)}
      mixes the key through SplitMix64 — the stream depends \textbf{only on
      its key}, never on execution order.
      \begin{itemize}\itemsep1pt
        \item Same history $\Rightarrow$ same draws on any thread, rank, pool
              size \emph{or batch} $\Rightarrow$ partition is valid by construction.
        \item Rank $r$ owns \code{[hist\_base + r$\cdot$N, \dots)} — disjoint
              streams $\Rightarrow$ MPI / Web-Worker splitting is trivial.
        \item Secondaries get \code{osh\_rng\_split()} from the parent —
              independent of scheduling.
        \item \code{struct osh\_rng} is 56\,B, pointer-free $\Rightarrow$
              copies to a GPU slot trivially.
      \end{itemize}
    \end{column}

%------------------------------------------------------------------------------
\begin{frame}{Strategy A — Multi-node / embarrassingly parallel}
  \begin{columns}[T]
    \begin{column}{0.46\textwidth}
      \small
      Each process is a \textbf{full, independent run} over a disjoint
      history range. Nothing is shared at runtime.
      \begin{itemize}\itemsep2pt
        \item Memory: every rank holds its \emph{own} copy of geometry +
              scoring grid.
        \item Communication: \textbf{none} until the end.
        \item Merge \code{.bdo} files; each carries its own \code{nstat}.
      \end{itemize}
      \textbf{Per-scorer merge rule} (scoring README):
      \begin{itemize}\scriptsize\itemsep1pt
        \item NORM (DOSE\dots): $\;X=\frac{\sum_j x_j}{\sum_j \mathrm{nstat}_j}$
        \item AVER (DLET\dots): $\;X=\frac{\sum_j x_j\,\mathrm{nstat}_j}{\sum_j \mathrm{nstat}_j}$
        \item SUM (COUNT): $\;X=\sum_j x_j$ \quad APPEND (MCPL): concat
      \end{itemize}
      \textcolor{oshGreen}{$+$} trivial, near-linear, robust.\quad
      \textcolor{oshRed}{$-$} grid replicated per rank (a problem for big CTs).
    \end{column}
    \begin{column}{0.54\textwidth}
      \centering
      \begin{tikzpicture}[scale=0.95]
        \foreach \r/\x in {0/0,1/2.5,2/5.0}{
          \node[worker,minimum width=2.0cm,minimum height=2.4cm] (w\r) at (\x,1.6) {};
          \node[ann] at (\x,2.55) {rank \r};
          \node[shared,minimum width=1.7cm] at (\x,2.05) {geometry\\(copy)};
          \node[private,minimum width=1.7cm] at (\x,1.35) {RNG +\\pool};
          \node[hot,minimum width=1.7cm] at (\x,0.65) {scoring\\grid};
          \node[lbl] at (\x,-0.05) {hist [\,$r\!\cdot\!N$, ..)};
        }
        \node[box,fill=oshGreen!12,minimum width=2.0cm] (m) at (2.5,-1.2) {merge \code{.bdo}\\$+$ weighting};
        \foreach \r in {0,1,2}{\draw[reduce] (w\r.south) .. controls +(0,-0.6) .. (m.north);}
        \node[lbl,below=1mm of m] {one total grid, total \code{nstat}};
      \end{tikzpicture}
    \end{column}
  \end{columns}
\end{frame}

\begin{frame}{Strategy B — Threads + per-thread scoring pages}
  \begin{columns}[T]
    \begin{column}{0.46\textwidth}
      \small
      One process, $T$ threads. Geometry \& material are
      \textcolor{oshGreen}{shared read-only}; each thread owns a
      \textcolor{oshAmber}{private particle pool and private accumulators}.
      \begin{itemize}\itemsep2pt
        \item No write contention during transport.
        \item One \textbf{reduction} (\code{merge()} the per-thread
              accumulators) at the end, then write a single \code{.bdo}.
        \item Exactly the $\sim$40-line driver PR \#162 unlocks: one
              \code{worker\_context} per thread, \code{run\_history\_range()},
              \code{merge}.
      \end{itemize}
      \textcolor{oshGreen}{$+$} no atomics, cache-friendly, deterministic
      reduction.\\
      \textcolor{oshRed}{$-$} scoring memory $\times\,T$ (the binding limit for CT).
    \end{column}
    \begin{column}{0.54\textwidth}
      \centering
      \begin{tikzpicture}[scale=0.95]
        \node[shared,minimum width=4.8cm] (geo) at (2.0,3.0)
              {shared, read-only: geometry $\cdot$ materials $\cdot$ LUTs};
        \foreach \t/\x in {0/0,1/2.0,2/4.0}{
          \node[worker,minimum width=1.7cm,minimum height=1.9cm] (t\t) at (\x,1.4){};
          \node[ann] at (\x,2.25){thread \t};
          \node[private,minimum width=1.4cm] at (\x,1.55){pool +\\RNG};
          \node[private,minimum width=1.4cm,fill=oshAmber!22] at (\x,0.85){private\\accum.};

\begin{frame}{Strategy C — atomic scoring: does ``each thread touches only a fragment'' save us?}
  \begin{columns}[T]
    \begin{column}{0.5\textwidth}
      \small
      Threads share \emph{one} grid and add into it with atomics — $O(1)$
      memory instead of $\times T$. A fair question:

      \smallskip
      \textit{each thread only \textbf{adds} into the bins its histories
      actually hit — a fragment, not the whole grid. If those fragments were
      \textbf{disjoint}, atomics would almost never collide and this would be
      nearly free.}
      \medskip

      They are \textbf{not} disjoint, because histories are partitioned by
      \emph{index}, not by \emph{space}:
      \begin{itemize}\scriptsize\itemsep1pt
        \item Every history's track runs down the same axis and piles into the
              \textbf{same Bragg-peak voxels} $\Rightarrow$ real collisions
              concentrate on the hot bins.
        \item Even non-colliding neighbours share a 64\,B line $\Rightarrow$
              \textbf{false sharing}.
        \item \textcolor{oshGreen}{Saving grace:} on a \emph{large} CT the cold
              majority of voxels is barely contended — so C scales \emph{better
              the bigger and sparser} the geometry.
      \end{itemize}
      \footnotesize\color{oshGrey}
      Spatial (domain) decomposition \emph{would} make writes disjoint — but
      then boundary-crossing histories need hand-off messaging. Only worth it
      if the grid doesn't fit in memory.
    \end{column}

\begin{frame}{Strategy D in practice — AVX widths and the GPU extreme}
  \begin{columns}[T]
    \begin{column}{0.52\textwidth}
      \small
      SIMD = one instruction, several \code{double} lanes. SoA is what lets the
      compiler use the \emph{wide} ones:
      \begin{itemize}\scriptsize\itemsep1pt
        \item \textbf{SSE2} 128-bit = 2 doubles (baseline everywhere).
        \item \textbf{AVX2} 256-bit = \textbf{4 doubles} + FMA — universal on
              every target node.
        \item \textbf{AVX-512} 512-bit = \textbf{8 doubles} + per-lane
              \emph{masking} — on Ares (Cascade-Lake Xeon) and Helios
              (Genoa EPYC); \emph{not} on Athena (Rome EPYC, AVX2 only).
              \footnotesize\textcolor{oshGrey}{(confirm per partition)}
      \end{itemize}
      \textbf{Why masking matters here:} histories diverge (step/die at
      different rates). AVX-512 masks let dead lanes sit idle without
      branching; on AVX2 we pad/compact instead (the pool already compacts).
      \medskip

      \textbf{GPU} is the same idea taken wide: a warp = 32 lanes in lockstep.
      Great throughput, but divergence and the cross-section working set bite
      harder $\Rightarrow$ a research spike, not a quick win.

\section{What the merge has to mean}
\begin{frame}{Statistics: the merge is also the variance contract (\#169)}
  \begin{columns}[T]
    \begin{column}{0.52\textwidth}
      \small
      Every strategy ends in the \textbf{same} step: fold per-worker partials
      into one result. That \code{merge()} also defines how \emph{uncertainty}
      combines.
      \medskip

      \textbf{Granularity:} true per-history variance needs
      \code{nbins$\times$live-histories} scratch — prohibitive for a CT. The
      wavefront design instead gives us \textbf{batches}, and a batch is
      \emph{already} what we produce:
      \begin{itemize}\scriptsize\itemsep1pt
        \item each worker / rank / lane-block = one batch,
        \item each periodic dump = a batch boundary,
        \item each independent run = a batch.
      \end{itemize}
      Crucially these batches are \textbf{unequal in size} (run-by-time, early
      finishers) — the normal case here, not an edge case.
    \end{column}
    \begin{column}{0.48\textwidth}
      \small
      \textbf{Two representations $\Rightarrow$ two merges:}
      \begin{itemize}\scriptsize\itemsep2pt
        \item \textcolor{oshAmber}{Additive} $\Sigma x,\Sigma x^2$:
              merge \code{=} \code{+=}, MPI is free \code{MPI\_SUM} — but
              cancellation on high-mean bins.
        \item \textcolor{oshGreen}{Welford/West $(n,\bar{x},M_2)$}:
              stable; merge is \textbf{Schubert--Gertz}
              \[ M_2 \mathrel{+}= M_{2,B} + \delta^2\tfrac{n_A n_B}{n} \]
              the cross-term a plain \code{+=} \emph{cannot} express.
      \end{itemize}
      \footnotesize\color{oshRed}
      Latent trap (\#169): today's \code{merge()} does a blanket \code{+=} over
      the variance arrays — correct only while they're NULL. The moment $M_2$
      lands there, it silently drops the cross-term. Decide the contract now —
      it's two functions, not a rewrite.
    \end{column}
  \end{columns}
\end{frame}

\begin{frame}{Reproducibility — a contract to state, not a blocker (\#168)}
  \centering
  \small
  Parallel MC is not bit-identical to serial — \code{double} addition isn't
  associative, so a different accumulation grouping differs at the ULP level.
  That is universal (Geant4, FLUKA, TOPAS). The physics is identical; only the
  \emph{sum order} changes.
  \vspace{2mm}

  \renewcommand{\arraystretch}{1.25}
  \begin{tabular}{l c l}
    \textbf{Property} & & \textbf{Why}\\
    \hline
    Bit-reproducible at a \emph{fixed} worker count & \textcolor{oshGreen}{\checkmark} & same ranges $\to$ same partials $\to$ same merge order\\
    Statistically identical to serial & \textcolor{oshGreen}{\checkmark} & same per-history physics; ULP-level only\\
    Bit-identical \emph{to} serial & \textcolor{oshRed}{$\times$} & FP non-associativity\\
    Bit-identical across \emph{different} worker counts & \textcolor{oshRed}{$\times$} & different grouping\\
  \end{tabular}
  \vspace{2mm}

  \begin{itemize}\scriptsize
    \item Nice-to-have, not the crux of this discussion — but worth a cheap CI
          guard: a fixed-worker run twice must be byte-identical (catches a
          stray shared-mutable global / race), plus a serial-vs-parallel
          agreement test reusing \code{compare\_dat.py}, and optionally a
          ThreadSanitizer job.
  \end{itemize}
\end{frame}

\section{Forward look}
\begin{frame}{Future physics: growing cross-section data (\#154, \#111)}
  \begin{columns}[T]
    \begin{column}{0.54\textwidth}
      \small
      Neutron transport (\#154), fragmentation (\#111) and later photons add
      \textbf{static cross-section tables} — condensed JEFF-3.3
      ($\sim$30 log-spaced points/nuclide for H,C,N,O,Ca + detector
      Li/B/He), optical-model fallback. The data grows; what does it do to the
      plan?
      \medskip

      \textbf{Good news: cross-sections are \textcolor{oshGreen}{shared,
      read-only} cold state.} Growth changes the shared box on the memory
      slide, not the writable one:
      \begin{itemize}\scriptsize\itemsep1pt
        \item \textbf{Threads (B/C):} tables load \emph{once} per node, read by
              all $T$ — no coherence traffic. Growth is nearly cost-free. This
              \emph{strengthens} the shared-memory path.
        \item \textbf{Process replication (A/MPI, WASM workers):} every rank
              copies the now-bigger tables $\Rightarrow$ favour
              \textbf{few ranks/node $\times$ many threads} (hybrid).
        \item \textbf{GPU (D):} tables become device working set; bigger +
              random (energy/nuclide) lookups $\Rightarrow$ more divergence.
              Keep them \emph{compact} — exactly why \#154 designs $\sim$30-point
              tables.
      \end{itemize}
    \end{column}
    \begin{column}{0.46\textwidth}
      \centering
      \begin{tikzpicture}[scale=0.9]
        \node[shared,minimum width=3.4cm,minimum height=1.4cm] (t) at (0,2.2)
          {cross-sections (ion + n + $\gamma$)\\\textbf{grows} — but read-only};
        \foreach \i/\x in {0/-1.2,1/0,2/1.2}{
          \node[worker,minimum width=0.9cm,minimum height=0.7cm,font=\tiny] (c\i) at (\x,0.4){thr};
          \draw[cflow](t.south)--(c\i.north);}
        \node[lbl,text width=4cm,align=center,font=\tiny] at (0,-0.4)
          {one copy feeds every thread\\$\Rightarrow$ threads scale through data growth};
      \end{tikzpicture}\\[1mm]
      \footnotesize\color{oshGreen}
      Net: bigger static data tilts the optimum \emph{toward} shared-memory
      threading and compact, GPU-friendly tables — it doesn't change the axis.
    \end{column}
  \end{columns}
\end{frame}

\begin{frame}{Licensing \& library choices}
  \small
  Project is \textbf{MIT} (permissive). Guiding rule: keep \code{osh\_core}
  dependency-free; every backend is \emph{optional} and must not impose
  copyleft on users.
  \vspace{1mm}

  \renewcommand{\arraystretch}{1.2}
  \footnotesize
  \begin{tabular}{l l l p{5.0cm}}
    \textbf{Layer} & \textbf{Options} & \textbf{License} & \textbf{Notes}\\
    \hline
    \textcolor{oshSky}{Threads} & \textbf{OpenMP} & rt.\ exc.\,/\,Apache & ubiquitous on HPC; matches \#162's driver sketch\\
     & POSIX \code{pthreads} & libc & full control, more boilerplate, no native Windows\\
     & C11 \code{<threads.h>} & std & portability gaps (older glibc, MSVC)\\
     & Intel TBB & Apache-2.0 & task-based, heavier, C++\\
    \hline
    \textcolor{oshGreen}{Multi-node} & Open MPI / MPICH & BSD-like & standard ABI; Intel/Cray MPI on the clusters\\
    \hline
    \textcolor{oshRed}{GPU} & CUDA & proprietary & NVIDIA-only (Athena A100, Helios Hopper)\\
     & HIP/ROCm, SYCL & MIT / Apache & cross-vendor; portability hedge\\
     & WebGPU & open & browser+native; \emph{no f64}, integer atomics only\\
    \hline
    \textcolor{oshAmber}{Browser} & Web Workers & --- & no library; the \#171 model (a)\\
  \end{tabular}
  \vspace{1.5mm}

  \begin{itemize}\scriptsize\itemsep1pt
    \item \textbf{Recommendation:} start with \textbf{OpenMP} (license-clean,
          one pragma layer, matches the existing \S4 driver); keep \textbf{MPI}
          optional/gated for cluster scale; defer the GPU API (CUDA vs.\
          SYCL/HIP) to a research spike. All behind CMake feature flags so the
          MIT core stays buildable with zero extra dependencies.
  \end{itemize}
\end{frame}

\section{Summary}
\begin{frame}{Comparison at a glance}
  \centering
  \renewcommand{\arraystretch}{1.3}
  \footnotesize
  \begin{tabular}{l l l l l l}
    \textbf{Strategy} & \textbf{Shares} & \textbf{Scoring mem} & \textbf{Best for} & \textbf{Repro.} & \textbf{Effort}\\
    \hline
    \textcolor{oshGreen}{A. Multi-node / MPI} & nothing & $\times$ ranks & cluster scale & bit-identical$^\ast$ & \textbf{low}\\
    \textcolor{oshSky}{B. Threads + accum} & geo (RO) & $\times T$ & CSG / small mesh & determ.\ reduce & medium\\
    \textcolor{oshAmber}{C. Threads + atomics} & geo + grid & $\times 1$ & large CT & order-dependent & medium\\
    \textcolor{oshRed}{D. SIMD / GPU} & geo (RO) & per lane/block & throughput ceiling & per-history stream & high\\
  \end{tabular}
  \vspace{3mm}
  \begin{itemize}\scriptsize
    \item[$\ast$] Per-history streams make A reproducible \emph{by construction}: rank $r$ owns a disjoint history range.
    \item \textbf{Workload picks the row:} CSG + mesh (compute-bound) $\to$ B;
          CT + CT scoring (memory-bound) $\to$ C; both compose under A across nodes.
    \item All four sit on the \textbf{same} foundation: read-only cold state +
          per-history RNG + SoA pool + one \code{merge()}.
  \end{itemize}
\end{frame}
